# Accessibility notes

- Every actionable icon-only control should have an accessible label and a sufficiently large hit target.
- Use native buttons/pressables with visible focus or pressed states where supported.
- Keep body text readable in both light and dark themes; do not rely on color alone to communicate a result.
- Loading states should announce progress using accessibility roles or labels.
- Error messages should be concise, visible, and associated with the relevant input when possible.
- Preserve text selection for detailed model output so users can inspect and copy results.
- Check layout at large text sizes and narrow screen widths.
- Decorative graphics should not create noisy screen-reader output.
- When presenting a score, include a textual explanation and limitation notice instead of only a colored bar.
